Sheet E of E · Platform

One data model, many places to publish it.

The site is built on entities that are independent of any MLS, IDX vendor or map provider, so the same system can later run another brokerage, a team, agent microsites or neighborhood sites.

E1 · EntitiesProvider-neutral core

Thirteen entities, scoped by tenant.

Every record belongs to a tenant, normally a brokerage. Sites are views over that data: a brokerage site, a team site, an agent page or an area microsite all read the same tables.

E2 · RelationshipsRules the UI depends on

Affiliation is data, not decoration.

The Title Block on every page is generated from these relationships, so a team can never be shown without its brokerage of record, and a listing never without its listing brokerage.

Teamn : 1BrokerageExactly one brokerage of record. The Oberdorfer Group → REWAP Brokerage LLC.
Personn : nBrokerageThrough License, which carries role and dates, so history is kept when people move.
Listingn : 1PropertyA property outlives its listings; price history and Sheets attach to the property.
Listingn : 1Listing brokerageMay be REWAP or another firm through IDX; attribution prints either way.
Propertyn : nAreaResolved by point-in-polygon against Area geometry: town plus any neighborhood.
AreatreeAreaMassachusetts → Central Massachusetts → Worcester → West Side. Regions group all 351 cities and towns; breadcrumbs and URLs follow the tree.
Articlen : nArea · PersonField Notes appear on every Sheet they are about, credited to named authors.
Listing provider adapter

Each IDX vendor is wrapped in an adapter that maps its feed to RESO Data Dictionary fields, then to REWAP’s Listing. Display rules, required attribution and refresh times live on the IDXProvider record, so switching vendors does not touch the UI.

Map provider adapter

The map style is a REWAP-owned style document (layers, colors, labels). Tiles, geocoding and routing sit behind one interface: MapLibre with OpenStreetMap vector tiles by default, replaceable without restyling.

E4 · AEO / GEOMachine-readable facts

Written so answer engines can cite it.

Search engines and AI assistants should be able to tell, without guessing, who REWAP is, where it works, who works there, which listings belong to whom, and how the Oberdorfer Group relates to it.

  • One JSON-LD graph per page, with stable @ids so the brokerage, office, founder, team and areas are the same nodes everywhere.
  • Each Sheet opens with an “At a glance” block of short, factual statements, each with a source and a reviewed date.
  • dateModified and named authors on Sheets and Field Notes.
  • Areas carry sameAs links to their Wikidata and official municipal pages.
  • Listings use schema.org RealEstateListing and always name the listing brokerage.
  • Placeholders such as license numbers are filled with verified values before launch; nothing unverified is marked up.
